# Atlas Profiler test plan

The suite should verify three contracts independently. Given tabular input, the profiler returns accurate metadata. Given saved metadata, the report renders it correctly. Given a large file, the profiler respects its sampling strategy and reports which metrics use the whole file.

The corpus is the `data/` folder of the UrbanTrace repository (for example `../urbantrace/data` next to this checkout). It contains 121 named GeoJSON files and 121 matching saved profiles, plus raw copies and two dataset-description catalogs. The named GeoJSON files total about 8.25 GiB. Use an optional `ATLAS_PROFILER_TEST_DATA_DIR` setting for corpus tests so contributors and CI can run the core suite without the sibling checkout.

Core tests need only the profiler. Report tests also need the report module (`profiler/report.py`) and pyautark, and check that the report renders the metadata the profiler produces.

## Test layers

| Layer | Inputs | When to run |
| --- | --- | --- |
| Core regressions | Small generated CSVs, TSVs, streams, and DataFrames under `tmp_path` | Every PR on supported Python versions. Include a job for each end of the declared Polars range. |
| Corpus integration | Selected files under `geojson/`, converted to tabular input in test setup | Opt-in local job or CI job with access to a pinned corpus snapshot. |
| Report integration | Profiles generated by the core suite and selected files under `metadata/` | Dedicated CI job with a known Autark revision and the installed wheel. Run one browser smoke test for the interactive output. |
| Performance | Fixed tall and wide generated CSVs plus selected large corpus files converted to CSV | Dedicated benchmark job. Track wall time and peak memory across runs on the same runner class. |

For corpus tests, assert the expected files exist when the suite is explicitly selected. Record fixture identifiers and file hashes for a pinned snapshot. Use Python's CSV parser, `datetime.strptime`, and direct coordinate arithmetic to calculate expected values from the input. The saved Atlas-style metadata serves as report input. Its counts and types reflect an earlier profiling run and may have different semantics.

## Corpus cases

Convert each GeoJSON feature's `properties` into one row. Select the fields listed below and preserve source strings, nulls, and row order. GeoJSON conversion belongs in fixture setup because the public profiler accepts tabular input. If a test derives a point from geometry, read GeoJSON coordinates in longitude, latitude order. Use `geo_classifier=False` for these deterministic checks.

| Dataset | Test and expected result |
| --- | --- |
| `NYC_libraries.geojson` | Profile all **253** point features through both the DataFrame and CSV paths. Assert that `latitude` and `longitude` form a pair with 253 points, that projected `xcoord` and `ycoord` do not form another pair, and that all-null `captype` is `MissingData`. Calculate the CSV envelope from the 0.1% and 99.9% coordinate quantiles, using the documented quantile method. Check that property coordinates and GeoJSON geometry agree within `1e-6` degrees. |
| `NYC_bicycle_counts.geojson` | Use a deterministic slice for the fast test and all **28,459** rows for the corpus run. Check that `lat`/`lon` and `geom_wkt` identify the same points when given the same rows. In a sampled CSV run, check **28,459** full-file lat/long pairs, sample-sized WKT coverage, and provenance that distinguishes the two entries. The full-file numeric count range is **0–759** and the mean is **719,179 / 28,459**. Parse the source dates with `%m/%d/%Y %I:%M:%S %p`. The endpoints are September 3, 2012 at 07:30 and August 17, 2025 at 03:00 under the profiler's UTC default for naive timestamps. |
| `2018_central_park_squirrel_census_squirrel_data.geojson` | Use the **3,023** records to test input normalization. Check that `running` is recognized as boolean. In a companion case, use declared `%m%d%Y` parsing to normalize the integer dates, and map `x`/`y` to longitude/latitude using the geometry as an independent check. Expect a single coordinate pair and dates from October 6 through October 20, 2018. Keep automatic recognition of the raw date integers and generic `x`/`y` names as a separate feature decision. |
| `NTA_Neighborhood_Tabulation_Areas.geojson` and `NYC_Bike_Routes.geojson` | Profile selected properties from **262** multipolygons and a bounded slice of **28,983** multilines. Check that identifiers such as `countyfips` and `segmentid`, and measurements such as `shape_area`, do not create point coverage. The test exercises the properties-only conversion and protects against accidental point inference. |
| `metadata/2013_yellow_taxi_trip_data.json` | Render the saved profile directly. Check that the overview shows **500,000** source rows and **739** profiled rows, that pickup and drop-off each have a distinct coordinate-pair map, and that both date fields appear in temporal coverage. Check sections, labels, and map data rather than snapshotting the entire HTML. |
| `metadata/NYC_libraries.json` and `metadata/NTA_Neighborhood_Tabulation_Areas.json` | Verify reports with spatial coverage and without spatial coverage. Check the distributions empty state on these profiles, which contain no histogram entries. Generate a fresh profile with `plots=True` in a separate reporting test and verify that it contains chart data. |

Check coordinate order independently for each backend. When comparing geohash totals, account for coordinates excluded by the configured envelope. Check that the density grid accounts for every in-envelope point through cell counts and the `outside` counter.

## Generated regression cases

| Case | Assertions |
| --- | --- |
| Delimited input contract | Parameterize CSV and TSV paths, `Path`, seekable streams, and DataFrame input. Include quoted delimiters, a quoted newline, UTF-8, empty fields, a header-only file, and an empty file. Assert the row and column counts, names, and documented empty-input behavior. Cover integer and duplicate DataFrame labels with an explicit success or validation-error contract. |
| Sample scope and late extremes | Write sorted rows with a distinct second region and timestamp range after the profiling prefix. Force a small `load_max_size` and assert `0 < nb_profiled_rows < nb_rows`. Compare whole-file numeric statistics, valid paired coordinates, and temporal endpoints with an independent full-file calculation. Check that histogram totals and provenance describe the profiled rows. |
| Coordinate validity and pairing | Include two named coordinate pairs, an unmatched axis, missing halves, out-of-range values, and a WKT point with asymmetric coordinates. Assert the exact valid count for each pair, longitude/latitude envelope order, and the documented policy for coordinates on the bounds. |
| Numeric and temporal robustness | Mix finite values with empty fields, `NaN`, and infinities. Check `json.dumps(profile, allow_nan=False)` and assert numeric summaries use finite values. Exercise explicit timestamp offsets, naive timestamps, and a manually annotated column with no valid dates. Assert UTC endpoints and the absence of a coverage crash. |
| Classifier side effects | Pass a fake classifier that returns a spatial label for a unique synthetic value. Run under `tmp_path`, capture INFO logs, and assert that the default call writes no file and logs no sample values. Exercise explicit diagnostics export if added. Keep real model evaluation as a separate opt-in test with a pinned checkpoint. |
| Wheel and report round trip | Install the wheel, generate a profile with `plots=True`, serialize it as strict JSON, and invoke `atlas-profiler-report`. Assert the exit code and meaningful output, including overview, distribution bins, coverage labels, and escaped column names. In the browser, assert that a histogram loads and inspect the map on a WebGPU-capable runner. |

Keep the existing CSV compatibility and sampling regressions. Add the implicit export, strict JSON, and mixed spatial provenance cases first. Use the library and bicycle cases for independent checks of coordinate order, projected-coordinate exclusion, temporal parsing, and full-file statistics. Keep exact timings and full-HTML snapshots out of pass/fail assertions.
